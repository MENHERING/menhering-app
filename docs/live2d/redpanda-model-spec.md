# 레서판다 Live2D 모델 제작 스펙 (#23 아바타 고도화)

> 목적: 첨부한 레서판다 캐릭터를 **크레이지 아케이드/Live2D 수준으로 살아 움직이는 2D 캐릭터**로 만들기 위한 제작 설계도.
> 대상 독자: 일러스트레이터 · Live2D 리거 · 프론트 연동 개발자.
> 상태: **이 문서는 초기 기획 설계도(historical)다.** 아래 배너의 "현재 구현 상태"가 실제와 맞다.

---

## ⚠️ 현재 구현 상태 (실제 모델과 이 스펙의 차이)

이 문서는 방향 검토 단계에 쓴 **이상적 설계도**다. 이후 redpanda 모델을 **자체 제작(DIY)·연동·테마·표정까지 완료**했고, 실제 구조는 몇 군데 다르다. 새로 참고할 땐 아래를 기준으로 볼 것.

- **실드로어블(10개)**: `tail`, `ear_L/R`, `arm_L/R`, `eye_L/R`, `heart`, `body_base`(크림 얼굴), `body_fur`(주황 털). §1의 세분 레이어(흰자/눈동자/**윗·아랫눈꺼풀** 분리 등)와 다르다.
- **눈**: `eye_L/R` **단일 메쉬**. 별도 흰자·눈꺼풀 드로어블 없음, 깜빡임은 메쉬 **키폼**(EyeOpen 0↔1)으로 처리. ⚠️ 감은 눈꺼풀이 한때 `body_fur` 텍스처에 그려박혀 있어 반개 시 삐져나오던 걸 2026-07-13 PSD에서 제거함.
- **이목구비**: 코·입·눈썹(brow_L/R)·볼(cheek)은 `body_base`에서 분리해 표정 리깅됨(§1의 별도 레이어 취지와 결과적으로 유사).
- **테마 색**: §3의 "전체 톤 vs 부위별" 결정은 **부위별 per-part Multiply로 확정·구현**됨(pixi7 + `pixi-live2d-display-lipsyncpatch` fork). 털은 그레이스케일 전제(`npm run assets:desaturate-fur`).
- **표정**: §2-3의 `.exp3` 파일 방식이 아니라 **코드에서 파라미터 직접 세팅**(`src/constants/mood-expression.ts` + `Live2DCharacter`의 mood 보간).
- **연동·렌더 상세·함정**: [frontend-integration.md](frontend-integration.md) 참고(싱글톤 앱, 재마운트 버그, 프레이밍, mood prop 등).

## 0. 큰 그림 (파이프라인)

```
[디자인 기준]        [1. 일러스트]           [2. 리깅]                 [3. 연동]
첨부 레서판다 이미지 →  레이어 분리 PSD 제작  →  Cubism Editor 리깅     →  Next.js 앱 배선
```

- 3단계(코드 연동)는 Claude가 함. POC로 이미 방식 검증됨.

## 1. 일러스트 레이어 분리 스펙 (일러스트레이터용)

Cubism은 **PSD의 레이어/폴더 구조를 그대로 부위로 가져온다.** 아래 부위를 **각각 독립 레이어**로 그린다.
핵심 원칙: **움직이거나 가려지는 부분은 무조건 분리**하고, **가려지는 뒤쪽도 잘리지 않게 온전히 그린다**(예: 눈꺼풀이 덮을 눈동자 위쪽까지 다 그림).

### 1-1. 머리 그룹 (`head/`)

| 레이어                         | 분리 이유                      |
| ------------------------------ | ------------------------------ |
| 귀 L / 귀 R (외곽 털)          | 흔들림 물리(귀 살랑)           |
| 귀 안쪽 크림 L / R             | 귀와 함께 움직임               |
| 귀끝 크림 털뭉치 L / R         | 물리 흔들림 강조               |
| 머리 베이스(주황 털)           | 얼굴 각도 변형의 기준면        |
| 얼굴 크림 무늬                 | 머리에 고정, 음영용            |
| 눈두덩 갈색 패치 L / R         | 레서판다 특징, 눈 주변 표정    |
| 크림 눈썹 점 L / R             | 눈썹 파라미터(표정)            |
| **눈 L / R — 흰자**            | (있다면) 눈 깜빡임 베이스      |
| **눈 L / R — 눈동자(홍채)**    | 시선 이동(EyeBall)             |
| **눈 L / R — 하이라이트/반짝** | 시선 반대로 살짝(생동감)       |
| **윗눈꺼풀 L / R**             | 깜빡임(EyeOpen)로 위→아래 닫힘 |
| 아랫눈꺼풀 L / R               | 웃을 때 살짝 올라옴            |
| 코                             | 얼굴 각도 따라 미세 이동       |
| **입**                         | 열림/미소 변형(MouthOpen/Form) |
| 볼터치(홍조) L / R             | ParamCheek 온오프              |

### 1-2. 몸 그룹 (`body/`)

| 레이어                          | 분리 이유               |
| ------------------------------- | ----------------------- |
| 몸통(주황)                      | 호흡·상체 각도 변형     |
| 배/가슴 크림                    | 몸통 앞면               |
| 왼팔+손, 오른팔+손(모으는 포즈) | 탭 반응/인사 모션(선택) |
| 하트 펜던트 + 끈                | 흔들림 물리(선택)       |
| 다리·발·돌(받침)                | 하단 고정, 무게중심     |

### 1-3. 꼬리 그룹 (`tail/`)

| 레이어                     | 분리 이유                          |
| -------------------------- | ---------------------------------- |
| 꼬리 마디 1~4 (뿌리→끝)    | **마디별 분리 = 꼬리 물리 흔들림** |
| 줄무늬(마디별 서브 레이어) | 마디 변형에 같이 딸려감            |

### 1-4. 제출 형식

- **PSD**, 캔버스 정사각(예: 2048×2048), 캐릭터 중앙.
- 레이어 이름 = 위 표 그대로(한글/영문 무관, 명확하게). 그룹은 폴더로.
- 배경 투명. 부위 간 **겹치는 뒤쪽도 온전히 채워서** 그림.

## 2. 리깅 파라미터 스펙 (Cubism Editor / 리거용)

우리 앱이 실제로 쓸 상호작용에 맞춘 **필수 파라미터**. (Cubism 표준 파라미터 ID 사용 → SDK 자동 연동 쉬움)

### 2-0. 권장 미니멀 리그 (MVP 시작점) ⭐

"**귀·눈·꼬리·손**"만 움직여도 충분히 살아있어 보인다. 여기서 시작 권장 — 레이어 분리·리깅 공수가 확 줄고 캐릭터는 여전히 귀엽다.

| 움직임                        | 필요 분리 레이어      | 비고                                                         |
| ----------------------------- | --------------------- | ------------------------------------------------------------ |
| **눈 깜빡임**                 | 윗눈꺼풀 L/R          | 생동감 가성비 1위, 필수                                      |
| **호흡**                      | (분리 불필요)         | `ParamBreath`로 몸·머리 미세 팽창 — 사실상 공짜              |
| **귀 살랑**                   | 귀 L/R (+귀끝 털)     | 물리                                                         |
| **꼬리 흔들**                 | 꼬리 마디 1~4         | 물리, 레서판다 시그니처                                      |
| **손 흔들기**                 | 팔+손 L/R             | 탭 반응 모션                                                 |
| **시선+머리 살짝** ⭐강력추천 | 눈동자+하이라이트 L/R | 포인터 따라봄 = "살아있음"의 핵심. 레이어 1쌍 추가로 체감 큼 |

- **빼도 되는 것(미니멀)**: 발(효과 미미 → 고정 레이어 OK), 입 표정, 볼터치, 눈썹.
- 물리(귀·꼬리)는 호흡/미세 idle 모션이 드라이버가 되어 작동한다.
- 아래 2-1~2-3은 **풀 스펙**. 미니멀에선 위 표에 해당하는 것만 리깅하면 된다.

### 2-1. 필수 (앱 상호작용에 직접 쓰임)

| 파라미터                           | 용도(앱)                                |
| ---------------------------------- | --------------------------------------- |
| `ParamAngleX/Y/Z`                  | 머리 각도 — **포인터/탭 위치 따라보기** |
| `ParamBodyAngleX/Y/Z`              | 상체 각도 — 머리 따라 자연스럽게        |
| `ParamEyeLOpen / ParamEyeROpen`    | **자동 눈 깜빡임**                      |
| `ParamEyeBallX / ParamEyeBallY`    | **시선 이동**(포인터 따라봄)            |
| `ParamMouthOpenY / ParamMouthForm` | 표정(웃음), 탭 반응                     |
| `ParamBreath`                      | **자동 호흡**(상시 idle 생동감)         |
| `ParamCheek`                       | 볼 홍조(기쁨 반응)                      |

### 2-2. 물리(Physics) — 자동 흔들림

- **귀 살랑 / 꼬리 흔들림 / 하트 펜던트 스윙**: `ParamAngleX/Z`, `ParamBodyAngleX` 를 입력으로 물리 연산.
- 부위 분리(1-1 귀, 1-3 꼬리 마디)가 되어 있어야 물리가 걸린다.

### 2-3. 모션/표정(선택, 있으면 좋음)

- **Idle 모션 그룹**: 상시 재생(느린 몸짓). SDK가 자동 루프.
- **Tap 반응 모션**: 캔버스 탭 시(예: 손 흔들기/웃음).
- **표정 파일**(.exp3): 기쁨/졸림 등 — 학습 상태(#23 감정 축)와 연결 여지.

### 2-4. 산출물(리거 → 개발자)

```
redpanda/
├─ redpanda.model3.json   (모델 설정 엔트리)
├─ redpanda.moc3          (리깅 데이터)
├─ redpanda.physics3.json (물리)
├─ redpanda.cdi3.json     (파라미터 표시명, 선택)
├─ textures/…png          (텍스처 아틀라스)
├─ motion/…motion3.json   (idle/tap, 선택)
└─ exp/…exp3.json         (표정, 선택)
```

## 3. ⚠️ 색상 테마(커스터마이징) — 미리 설계할 것

현행 아바타의 "색 테마" 기능은 **SVG fill 교체** 구조라 Live2D에선 그대로 안 된다. 두 가지 경로:

### 방식 A — 런타임 부위 색 틴트 (권장, 프로토타입 필요)

- Cubism 4.2+ 의 **ArtMesh Multiply/Screen Color** 를 SDK에서 런타임 지정(`setMultiplyColor` 등).
- 몸 털·귀·꼬리 등 **테마 대상 부위를 별 ArtMesh로** 두면, 코드에서 색을 곱해 **테마별로 색만 바꿔** 렌더 가능.
- 주의: **틴트(곱셈)** 라 완전 교체가 아님 → 원본 아트를 **약간 채도 낮은 톤**으로 그려야 틴트가 예쁘게 먹음. **POC로 실검증 필요**(정확 동작은 SDK 버전 의존).

### 방식 B — 테마별 텍스처 세트

- 테마마다 텍스처 png 세트를 따로 만들어 로드. 단순하지만 **에셋 N배 관리**.

### 프로토타입 결과 (2026-07-06, `spike/#23/live2d-poc`) ✅

> ℹ️ 아래는 2026-07-06 프로토타입 시점의 **historical 기록**이다. §3의 "전체 톤 vs 부위별" 결정은 상단 배너대로 **부위별 per-part Multiply로 확정·구현**됐다([frontend-integration.md](frontend-integration.md), `Live2DCharacter`의 `tinted` 참고).

- **런타임 색교체 자체는 앱에서 검증됨.** 샘플 모델에 테마 색 적용·전환·복원 동작, 그동안 애니메이션(호흡·깜빡)도 유지.
- 단, 검증에 쓴 건 **Pixi ColorMatrixFilter = 전체 균일 틴트**(모든 부위 동시 곱셈). `pixi-live2d-display@0.4.0`은 네이티브 per-part multiply(`setDrawableMultiplyColor`)를 **노출 안 함**(undefined). 로드된 Cubism Core는 4.2(드로어블 134개 감지)라 **코어 차원 지원은 존재**.
- **판정:**
  - "캐릭터 전체 톤만 바꿔도 OK" → **필터 방식으로 지금 바로 가능**.
  - "털만 테마색, 눈·크림·코는 유지"(부위별) → **네이티브 per-part Multiply 필요** = Cubism Web Framework 직접 사용 or per-part API 노출하는 최신 plugin fork로 배선. 코어가 지원하므로 실현 가능(연동 추가 작업).
  - 원본 아트는 **채도 약간 낮게** 그려야 곱셈 틴트가 예쁘게 먹음.

> ~~결정 필요: 테마를 **전체 톤 틴트**로 갈지 **부위별(털만)**로 갈지 → 전자는 즉시, 후자는 per-part 배선 추가.~~ → **결정됨: 부위별 per-part Multiply로 배선 완료**(상단 배너 참고).

## 4. 앱 연동 계획 (개발자 = Claude, 3단계)

- 에셋을 `public/live2d/redpanda/` 에 배치.
- `CharacterRenderer`(현행 SVG 스위처)를 **Live2D 렌더러로 교체/공존**하는 어댑터 작성.
  - 4종 캐릭터 중 레서판다만 우선 Live2D, 나머지는 기존 SVG로 폴백 가능(점진 전환).
- idle/blink/breath 자동, 포인터 팔로우(`autoInteract`), 탭 모션 배선. (POC에서 방식 검증됨)
- `prefers-reduced-motion` 시 모션 최소화(정지 포즈).
- 테마 색은 §3 방식 A로 `setMultiplyColor` 배선.
- 번들: 프로덕션은 Pixi+Cubism Core 번들 포함(무거움) → 아바타 탭 **동적 import/지연 로드**로 초기 로드 보호.

## 5. 리소스 & 의사결정 (팀)

### 5-1. DIY vs 외주

- **직접**: Cubism Editor **FREE 버전**으로 이 규모(1캐릭터) 리깅 가능. 단 일러스트 레이어링 + 리깅 **학습 곡선** 있음.
- **외주**: Live2D 리거에게 의뢰(스케브/Booth/피버 등). "레이어 PSD 제공 시 리깅만" vs "일러스트+리깅 풀패키지" 견적 상이.

### 5-2. 라이선스

- Cubism SDK: 개인·소규모(연매출 1000만엔≈$67k 미만) **무료**, 초과 시 퍼블리케이션 라이선스 유료.
- 첨부 레서판다 이미지의 **원저작권/사용권** 확인(AI 생성이면 생성물 이용약관, 타인 작품이면 사용 불가).

### 5-3. 공수 감각(대략)

| 단계                 | 담당           | 대략   |
| -------------------- | -------------- | ------ |
| 레이어 분리 일러스트 | 일러스트레이터 | 수일   |
| 리깅(파라미터+물리)  | 리거           | 수일   |
| 앱 연동              | Claude         | 수시간 |
| 테마 틴트 프로토타입 | Claude         | 수시간 |

→ **다일·다역할 작업. 한 세션/하루 완성 불가.** 사람 리소스(일러스트+리깅) 확보가 선행.
